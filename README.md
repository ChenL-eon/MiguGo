# MiguGo

MiguGo 是一个使用 Flutter 编写的个人练习项目：在 Windows 与 Android 上浏览咪咕音乐公开曲库、在线流式播放歌曲与查看同步歌词。首页是调用咪咕官方推荐数据的每日推送页，歌单页会把登录账号的「我喜欢的音乐」、自建与收藏歌单读出来，也可以把网易云、QQ音乐、酷狗的歌单按分享链接导入并匹配到咪咕曲库。界面全部使用 Flutter 自绘，登录也在账号弹窗里原生完成——短信验证码与账号密码直接提交给咪咕通行证，本机不留存；只有两处会临时打开网页——原生登录遇到官方风控时按需打开的官方通行证登录窗口，以及播放页为 VIP 曲目内嵌的咪咕官方网页播放器。系统浏览器登录与手动粘贴 Cookie 已经取消；登录后的左下角卡片是个人中心，退出登录与切换账号都在这一屏完成。

> 本软件【MiguGo】仅为个人学习练习项目，非咪咕官方软件，仅供本人自用，不对外分发；音乐版权归属咪咕及对应版权方。

## 功能

- **首页推送**：调用咪咕官方每日推荐模板与首页栏目配置，展示「今日推荐」歌曲列表与「精选歌单」横向卡片；支持下拉刷新、开始播放任意一首（移动端单击，桌面端双击）、打开推荐歌单，刷新失败时保留上一次成功的内容。推荐内容由咪咕按当天与账号状态下发，应用只做展示。
- **搜索**：单曲与公开歌单双 Tab，展示歌曲名、歌手、专辑，支持失败重试，并记录最近 10 条搜索历史。单曲搜索按咪咕接口的 20 条 / 页逐页追加，结果底部提供「加载更多」，不再把第一页的 20 条当成全部结果。
- **歌单导入**：导航第二项，导入入口收在页面右上角的「导入歌单」小按钮里，点击后在弹窗中粘贴网易云音乐、QQ音乐或酷狗音乐的歌单分享链接（短链接会先跟随跳转解析）。应用读取该歌单的公开曲目名与歌手，逐首搜索咪咕曲库并保留原歌单顺序；最多保存 20 个导入歌单，可查看匹配/未匹配明细、整单播放或删除。单次最多扫描 500 首；匹配时并发 4，遇到咪咕限流会立即停下并提示稍后再试。
- **我的音乐**：登录咪咕账号后，歌单页顶部自动读取「我喜欢的音乐」、自建歌单与收藏的歌单；只读，不新建、不收藏、不改动账号内容。点开任意一张即可分页加载歌曲并整单播放；未登录时这里显示登录入口，退出登录后随凭据一起清空。
- **咪咕歌单**：封面、创建者、标签、简介与歌曲列表，可整单播放或从任意一首开始播放。
- **播放**：封面、歌曲信息、逐行同步歌词、进度拖动、音量调节、上一首 / 下一首、单曲循环 / 列表循环 / 随机播放，睡眠定时。支持选择标准音质 / 高品质 / 无损音质，实际档位由咪咕按账号权益发放，不允许时自动回退。免费曲目与已登录账号的 VIP 曲目都走原生播放；咪咕拒绝发放地址时，可在同一面板切到「官方播放器」，由咪咕网页兜底。
- **设置**：浅色 / 深色 / 跟随系统主题、玫粉 / 晴蓝 / 青绿 / 琥珀 / 紫罗兰五种主题色、环境光晕、默认播放模式、播放音质、音量记忆、歌词自动滚动、睡眠定时、搜索历史、快捷键开关与恢复默认；所有改动即时生效并保存在本机。
- **系统媒体集成**：Android 通知栏与锁屏控制、后台播放、音频焦点；Windows SMTC 系统媒体卡片、全局快捷键。
- **账号权限**：桌面左下角的账号卡片与移动端「我的」页点开就是原生登录弹窗，同一屏里给出登录状态与权限说明，弹窗底部一句凭证提示后可点「隐私政策」就地展开全文；表单用两个胶囊页签切换短信验证码与账号密码，整屏不出现网页。只有原生登录被官方风控拦下时才按需打开官方通行证登录窗口，读到凭证后该窗口立即关闭。是否可播放完全由咪咕按账号权益判定，应用只携带用户自己的凭据发起请求。
- **关于页**：固定展示用途与版权声明、更新开关、合规边界与实现说明。

软件默认跟随系统明暗，强调色默认为玫粉。可在「设置 → 外观」中切换浅色 / 深色 / 跟随系统，并从玫粉、晴蓝、青绿、琥珀、紫罗兰五种主题色里选择强调色；主题色只改强调色及其联动色，不改变明暗模式。播放页的沉浸配色固定为白阶，不受主题色影响。Windows 原生标题栏与 Android 系统栏会同步明暗主题。

## 合规边界

项目在实现上固定遵循以下边界，不提供任何绕过手段：

- 账号权限完全跟随咪咕官方：只有登录咪咕账号、且该账号拥有对应曲目权益时，才可能拿到播放地址。禁止实现歌曲下载、音频文件解密、本地持久保存音频文件，仅在线流式播放。
- 原生登录只调用咪咕通行证与音乐站的会话接口：取一次 RSA 公钥，把用户当场填写的手机号、验证码或密码加密后提交，再用返回的票据换音乐站会话。代码里不含任何账号密钥，也不生成官方风控签名；密码与验证码只在本次请求中出现，本机不落盘、不写日志。
- 图形验证码只显示咪咕自己下发的原图，由登录者本人照着输入，应用不做识别、不自动作答，也没有引入任何图像识别依赖；官方改要滑块这类本应用无法呈现的验证形式时，只做说明并交给官方页面登录。
- 登录弹窗与原生登录面板本身是原生的，只有点击「改用咪咕官方页面登录」时才临时打开一个加载咪咕官方通行证页面的登录窗口，读到凭证后该窗口立即关闭；播放页只为 VIP 曲目内嵌咪咕官方网页播放器；两处 WebView 都只显示咪咕自己的页面，其余界面全部为原生 Flutter。不读取内嵌播放器页面里的音频地址；登录只通过原生登录或官方登录窗口完成，应用内没有手动粘贴 Cookie 与系统浏览器登录的入口。只在 Windows 上于这些页面与本机之间同步同一个账号的登录会话，其余 Cookie 一概不取。
- 所有咪咕请求只对接咪咕网页公开接口；登录后以只读方式读取本账号的我喜欢、自建与收藏歌单；只有用户主动导入歌单时，才会读取对应平台公开歌单的曲目名与歌手，用于匹配咪咕曲库。不登录第三方账号、不读取第三方 Cookie、不下载音频、不引入批量抓取逻辑。

具体实现约定：

- 播放音质只使用咪咕官方的三档标识：`PQ`（标准音质）、`HQ`（高品质）、`SQ`（无损音质）。应用按所选档位请求，账号没有对应权益时逐级回退；免费曲目最终仍可回退到 `listenSong.do` 的标准音质。不实现音频下载、音频文件解密或本地音频持久化。
- 免费曲目的地址由 `listenSong.do` 以 302 临时重定向下发；VIP 曲目的地址由 `strategy/pc/listen/v2.0` 按账号权益下发。两种地址都直接交给 `just_audio` 在线流式播放；因链接过期导致加载失败时，同一首歌会自动重取一次，仍失败就提示重试。
- VIP 曲目只有在**本机存在 `pacmtoken` 凭据**时才发起取链请求；接口没给地址时，提示里转述咪咕返回的 `dialogInfo` 文案（如“会员专属音质”），不做任何本地提权，同时保留「官方页面播放」入口作为兜底。
- 所有请求自动携带 `Referer: https://music.migu.cn`、本机 `deviceId` 以及已有的 `uid` / `pacmtoken` / `msisdn` 请求头；Cookie 只附加到 `migu.cn` 及其子域，不写入日志、不在界面显示具体值。
- `deviceId` 由 `lib/core/utils/device_identity.dart` 提供：Android 通过 `MainActivity` 的 `migu_lele/device` 通道读取 `Settings.Secure.ANDROID_ID`，Windows 等其他平台首次启动生成随机 UUID 并存在本机偏好里。它只是一个稳定的设备侧标识，用来把同一账号的多端会话区分开，不参与任何登录签名，也不读取 IMEI、序列号等敏感信息。
- 服务端通过 `Set-Cookie` 下发的 Cookie 优先于手动快照；应用按 `Domain`、`Path`、`Secure`、`Max-Age`、`Expires` 更新、替换或删除。只有 Cookie 罐里确实还有可用的同名值时才压住手动快照，因此服务端轮换会覆盖旧值，而一次 `Max-Age=0` 删除不会让登录凭据从此不再发送。登录快照（`mg_auth_pacmtoken`、`mg_auth_uid`、`mg_auth_msisdn` 等）本身不带过期时间，整个 Cookie 罐也会全量备份进系统安全存储并在启动时重建，所以重启动不会丢登录态。
- 咪咕没有 refresh token，失效只能由用户重新登录；但原生登录时通行证签发的登录票据会留在本机（`PassportTicketStore`，与 Cookie 分开存放），账号接口回绝凭据时先用它静默换一次新 `pacmtoken`（`token-validate/v3.0`），换到了就继续用，换不到才进入下面的取证流程。应用因此另有**前台保活**（`lib/services/auth/session_keep_alive.dart`，只在应用可见时每 4–6 小时用本机凭据只读请求一次账号资料，退到后台立即取消定时器，启动时不会额外打网络）与**鉴权失败取证**（判定放在拦截器里，因为只有那里拿得到真实请求地址——业务码 `290001 请先登录` 是随 HTTP 200 回来的。只有本身就要求登录的账号接口，即 `isLoginScopedEndpoint()` 认下的用户资料与账号歌单那几个路径，在本地确实带过 `pacmtoken` 时回绝，才算一次失效证据；歌词、封面、公开搜索的 401 与 HTTP 403 只留记录、不参与判定，未登录的公开请求更不会骚扰用户）两套机制，续期就挂在取证之后。证据由 `SessionRejectLedger`（`lib/services/auth/session_reject_ledger.dart`）记下最近一条：接口地址、HTTP 状态码、业务编码与那句服务端文案，服务端文案先经 `sanitizeInfo()` 过滤，不含任何凭据内容。第一次回绝只把状态降级为「登录可能已失效」并**保留凭据**；隔过 30 分钟（`confirmGap`）账号接口再次回绝，才认定这份凭据确实作废，于是保活永久停摆并自动走一遍退出登录（清凭据、清账号快照、停止播放并清空队列），登录面板顶部直接引用那条证据，说明是咪咕拒绝而不是用户自己退的。期间账号接口只要有一次成功回包就把计数清零，重新登录与手动退出则连证据一起清掉。续期只在账号接口回绝后触发，且 10 分钟内最多一次（进行中的续期会吞掉同批拒绝）；成功就清零计数、静默继续，票据缺失、被咪咕拒绝或仍在冷却期时不再重试。续期不是重登：应用不会自动重登，官方页面登录没有登录票据，也从不主动续期。
- 不生成官方登录签名、不做音频解密、不批量抓取；官方登录窗口读到凭证后立即清理其 WebView 会话并关闭。Windows 上内嵌播放器与登录窗口使用相互隔离的浏览器目录，清理时只清登录目录，不会抹掉播放器 profile 里咪咕写入的会话；Android 两处 WebView 共用系统 WebView 的 Cookie 库，登录页退出时按咪咕站点逐条删除 Cookie，不整份清空。Windows 的播放页还会同步本机账号的登录会话 Cookie；页面本身只允许停留在 `https://*.migu.cn`。
- 首页推送直接使用咪咕网页的推荐模板数据，应用只补一个本机生成的 `imei` 设备号，不伪造账号身份，也不缓存推荐结果到磁盘。
- 外部歌单导入使用独立的网络客户端：不带咪咕 Cookie、不带第三方 Cookie、不读取浏览器数据，只对用户主动粘贴的链接发起公开 GET 请求；不登录第三方平台，也不把外部歌单的音频地址带进应用。

## 隐私政策

正文常量在 `lib/core/constants/app_constants.dart` 的 `AppConstants.privacyPolicy`，由 `lib/widgets/privacy_policy.dart` 渲染。登录弹窗底部只留一句凭证去向提示，句尾的「隐私政策」按钮点开就是完整正文的详情窗口，关掉回到登录页；关于页不再重复这一份（那里的隐私政策模块已删除，正文只此一处）。内容只写实现里真实发生过的事：

| 条目 | 要点 |
| --- | --- |
| 政策范围 | 没有自建服务器与中间层，数据只在本机与咪咕官方接口之间来回；账号信息如何处理以咪咕官方政策为准 |
| 登录时提交出去的信息 | 手机号、短信验证码、账号与密码都用当场下发的 RSA 公钥加密后直接提交给通行证，只存在于那一次请求 |
| 登录之后保存在本机的是什么 | 会话凭据写入系统安全存储：Android 走 Keystore，Windows 是 DPAPI 按当前用户加密的密文；原生登录落 `pacmtoken` 和通行证签发的登录票据（票据不随普通请求发送，只用于回绝时换一次新会话），官方页面登录会保存页面写下的咪咕登录 Cookie |
| 图形验证码 | 显示咪咕下发的原图，由本人照着输入，不识别不代答；验证码会话只在内存中，随本次登录结束丢弃 |
| 设备标识与固定请求头 | `deviceId`（Android 为 `ANDROID_ID`，其余平台为随机 UUID）只发给咪咕；`fingerPrint` 在每次启动时生成一次、本次运行内复用（不是真实指纹），`imei` / `imsi` 固定填 `h5page` |
| 本机保存的其余内容 | 设置项、搜索历史（最多 10 条，可关可清）、导入歌单及其咪咕侧匹配结果；无播放历史、无收听统计 |
| 数据流向的网络地址 | 只有咪咕自有域名，两处例外：咪咕 302 指向自己的音频 CDN，导入歌单的封面来自来源平台 |
| WebView 里产生的数据 | Windows 上两处各有独立目录：登录目录的 Cookie 离开登录页时清除，播放器目录的会话与网页缓存不会被本应用清除；Android 跟随系统 WebView 的本应用存储，离开登录页只删除咪咕站点的 Cookie，不整份清空 |
| 日志与第三方组件 | 无统计 / 广告 / 崩溃上报 / 自动更新组件，无日志文件，界面与提示不回显 Cookie 值 |
| 系统权限 | Android 清单只声明 `INTERNET`，其余前台服务与通知类权限来自播放插件 |
| 如何清除本机数据 | 个人中心里的「退出登录」与「切换账号」清除本机登录凭据、登录票据与账号快照、停止播放并清空队列，不动设置、搜索历史与导入歌单；原生登录的账号会先用留存票据静默换一次新会话，换到了不算回绝；换不到时，要求登录的账号接口两次回绝凭据（401 / 请先登录，两次相隔 30 分钟以上）才按同样方式自动退出一次，单次回绝只提示并保留凭据；403 与公开接口的 401 不算失效；咪咕没有登出接口，退出不通知服务端，彻底清除靠系统「清除应用数据」或删除本机应用数据目录 |

## 接口说明

应用只对接咪咕面向网页端公开的接口，按用途分为以下几类：

| 用途 | 说明 |
| --- | --- |
| 搜索 | 单曲与公开歌单检索，分页追加 |
| 歌单 | 公开歌单详情与歌曲列表 |
| 播放取链 | 免费曲目走临时重定向地址；VIP 曲目按账号权益走播放策略接口 |
| 首页推荐 | 每日推荐模板与首页栏目配置 |
| 登录 | 通行证公钥、账号密码 / 短信登录与图形验证码 |
| 会话交换 | 登录票据换取音乐站会话，供原生取链使用 |

本节不再逐条列出具体主机、路径与参数；实现集中在 `lib/services/api/` 与 `lib/services/auth/`。这些接口属于非官方公开网页接口，可能随时调整或限制访问。

### 原生登录协议

登录链路的请求依次发生，除公钥外都带 `Referer: https://passport.migu.cn/login` 与 `Origin: https://passport.migu.cn`：

1. `POST /password/publickey` 取 `result.modulus` 与 `result.publicExponent`（均为 16 进制字符串）。公钥每次登录重新取，官方会轮换。
2. 用取到的 modulus 与指数对输入做 RSA（PKCS#1 v1.5 type-2 填充，输出小写 16 进制、不补齐宽度），与官方网页的 jsbn 实现逐位一致；纯 Dart 用 `BigInt.modPow` 完成，见 `lib/services/auth/migu_rsa.dart`，没有引入额外依赖。
3. `POST /authn`（`loginID` + `enpassword`，`imgcodeType=1`、`appType=0`、`relayState=`）或 `POST /authn/dynamicpassword`（`msisdn` + `dynamicPassword`，`imgcodeType=2`、`securityCode=7619`）；发短信用 `GET /login/dynamicpassword`。`sourceID=220029`、`isAsync=true`、`fingerPrint`/`fingerPrintDetail`（应用启动时生成的 32 位随机 16 进制串，整个运行期间复用，官方用它当浏览器指纹，本机不采集任何真实指纹）是表单常量。成功返回 `status=2000` 与 `result.token`。
4. 被风控时先补两步图形验证码，然后回到第 3 步重投一次：
   - `GET /captcha/graph/risk?imgcodeType=&showType=&sourceid=220029` 取图。响应的 `result.captchaurl` 本身就是 `data:image/jpeg;base64,…` 图片，应用剥掉前缀还原成字节显示在表单里，`imgcodeType` 沿用登录方式的编号（1=账号密码、2=短信），`showType` 0 是首次加载、1 是官方页面的「换一张」。响应同时用 `Set-Cookie` 下发 `mgnd_session_id` 等通行证会话 Cookie，验证码答案就记在这份会话上，取图、校验与随后的登录必须共用同一份，否则等于每次重新回答。
   - `GET /captcha/graph/check?imgcodeType=&captcha=&sourceid=220029` 把用户照图输入的字符**明文**交给官方认一次，不对时返回 `4002 验证码错误或已失效`，界面提示换一张重填。认过之后才重新提交登录，登录表单里的 `captcha` 同为用户输入的明文。

   这条链路里的图片始终原样显示、答案始终由人输入，应用不做任何识别或自动作答。咪咕若改要滑块（`/captcha/sliding`，官方 `getability` 脚本在账号被判定存在安全风险时下发这条路径）等本表单呈现不了的形式，只做提示并引导改用官方页面。
5. `GET user/h5/token-validate/v3.0?token=&type=2&sourceId=220029&activityId=MUSIC-WWW`，请求头带 `Cookie: idmpauth=true@passport.migu.cn`，由 `Set-Cookie` 拿到 `pacmtoken`——原生 VIP 取链唯一需要的凭据。只有这一步成功才算登录完成。写进安全存储的是这一步下发的 `pacmtoken` 与本次登录票据：前者用于取链，后者只留着在账号接口回绝时再换一次新会话，不随普通请求发送。

登录用的 Dio 与全局网络层完全分开：不携带本机旧的 `pacmtoken` 与统计 Cookie，一次失败的登录不会污染已有会话。通行证会话 Cookie 只在这一份 Dio 实例的内存里按域名保存，只发给 `passport.migu.cn`，换票请求仍然只带 `idmpauth` 那一条声明，且不落盘。失败提示只包含自己组织的中文文案与咪咕返回的状态码，绝不回显密码、验证码、票据或 Cookie 值；接口调整或验证码做不到时，界面会明确引导改用「使用咪咕官方页面登录」。

单曲搜索还有一个固定行为：`pageSize` 传 20、30、50 或 100，响应都只返回 20 条，只有 `pageNo` 生效。应用因此固定按 20 条一页请求，并在结果底部用 `pageNo + 1` 追加下一页，同时对 `contentId` 去重。

`listenSong.do` 的实测行为（同一请求只更换曲目与是否携带 Cookie）：

| 曲目 | 是否携带 Cookie | 返回 |
| --- | --- | --- |
| 免费曲目（如断桥残雪） | 任意 | `302` + `Location` 明文时效地址 |
| VIP 曲目（如孤勇者、普通朋友、我的地盘） | 携带有效 Cookie | `200` + `{"code":"200002","info":"PE参数格式错误"}` |
| 同上 | 完全不携带 Cookie | 与上一行**逐字相同** |

这条接口只为免费曲目发放地址，VIP 曲目的拒绝与本机登录状态无关，因此 VIP 曲目改走网页播放器使用的策略接口。应用把 `200002` 归类为“接口不发放该曲目地址”，不提示“登录可能已失效”，也不改变账号状态。

### VIP 曲目：原生取链与官方网页播放器

VIP 曲目使用咪咕网页播放器自己的取链接口：

`GET https://app.c.nf.migu.cn/strategy/pc/listen/v2.0?scene=&netType=01&resourceType=2&copyrightId=<id>&contentId=<id>&toneFlag=<PQ|HQ|SQ>`

- 请求头除 `Referer` 与 Cookie 外，还带本机 `uid` / `pacmtoken` / `msisdn`，以及站点用来判断是否编码响应的 `signature: 1`、`birth: h5page`。
- 响应体是站点自己的编码：4 字节头 `AB CD 01 <偏移>`，正文逐字节为 `明文 + 偏移 - 密钥`，密钥随网页 SDK 下发。`lib/services/api/migu_response_cipher.dart` 只负责还原这层 JSON 信封，**不涉及音频文件解密**。
- 从「设置 → 播放 → 播放音质」选择的档位开始，按 `SQ → HQ → PQ` 逐级回退；是否发放地址完全由咪咕按账号权益决定。
- 没有地址时，接口会在 `data.dialogInfo.text` / `data.cannotCode` 里给出原因（实测匿名请求 VIP 曲目 HQ 返回 `440022`“会员专属音质，请先登录”），应用直接转述这段文案，并在提示中列出已尝试的档位；需要单独购买的数字专辑同样由服务端拒绝。
- 播放地址只交给 `just_audio` 在线流式播放，不下载、不落盘。

### 播放音质

| 档位 | 咪咕标识 | 设置页文案 | 说明 |
| --- | --- | --- | --- |
| 标准音质 | `PQ` | 标准 | 约 128 kbps，免费曲目的兜底档位，无需登录即可请求。 |
| 高品质 | `HQ` | 高品质 | 约 320 kbps，由账号权益决定是否发放。 |
| 无损音质 | `SQ` | 无损 | FLAC 无损，由账号权益决定是否发放。 |

- 默认「高品质」。免费曲目在未登录时直接走 `listenSong.do` 的标准音质；已登录并选择更高档位时，先尝试策略接口，失败后自动回退 `listenSong.do`，保证仍能试听。
- VIP 曲目从所选档位开始逐级回退；没有任何可用地址时给出服务端原因与已尝试档位，并保留「官方播放器」兜底。
- 设置项会持久化到本机；切换后从下一首开始生效，正在播放的歌曲不会被打断。
- 实际音频以咪咕发放的为准；播放页不额外标注码率，避免把服务端结果误报成“已获得无损”。

如果原生取链被咪咕拒绝，播放页仍提供「官方播放器」面板作为兜底——它是咪咕自己的页面，登录、鉴权、取链都在页面里完成：

- 地址为 `https://music.migu.cn/v5/#/playlist?search=<歌名>&playlistType=ordinary`。v5 是 hash 路由的单页应用，路由只有 `musicLibrary`、`playlist`、`albumDetail`、`singerDetail` 等，**没有歌曲详情页**，`music.migu.cn/v3/music/song/<id>` 之类旧地址一律 301 回 `/v5/`，搜索结果页是唯一直达某一首歌的入口。
- 歌名取自接口返回的 `songName`，会先去掉括号（`(`、`（`、`[`、`【`）及其后面的括注，否则「孤勇者(《英雄联盟：双城之战》主题曲)」整串搜索反而找不到。
- Windows 上面板使用独立的用户数据目录 `%LOCALAPPDATA%\migu_lele\webview2_player`，与官方登录窗口的 `webview2` 隔离：登录窗口进出时会清空自己那份 Cookie，不能连带抹掉播放页里咪咕写入的登录会话；Android 没有独立目录，两处共用系统 WebView 的 Cookie 库。
- 面板只加载 `https://*.migu.cn` 的页面，其余跳转一律取消；不执行 `evaluateJavascript`，不解析页面内容，也不读取音频地址。用户在这个页面里点咪咕的「登录」，用咪咕自己的方式登录，权限判定完全在咪咕服务端。
- Windows 上登录会话由 `WebSessionSync`（`lib/services/auth/web_session_sync.dart`）在面板与原生请求之间双向同步（Android 不支持，`WebSessionSync.supported` 为假，网页会话只留在系统 WebView 里）：`onLoadStart` 时把本机手动快照里登录相关的名称（`mg_auth_*`、`pacmtoken` 等）写进 profile，`onLoadStop` 后从 profile 读回并只更新这些名称，让官方页面续签出的新会话顺带给本机续期。写读都带 6 秒超时，且发生在 WebView 已创建之后，避免 `CookieManager` 在无 WebView 实例时挂住；同步失败只跳过这一次，不影响页面。

### 首页推送

- 每日推荐：`GET https://app.c.nf.migu.cn/pc/v1.0/template/todayRecommendList/release?actionId=1&index=1&templateVersion=5`，读取 `data.recommendData.data`，其字段与搜索接口一致，可直接映射为歌曲模型；`time` 字段是推荐日期。
- 精选歌单：`GET https://app.c.nf.migu.cn/pc/bmw/page-data/music-index-show/v2.0?templateVersion=1`，取 `view == 'ZJ-SongList-Scroll'` 的栏目，解析其中的 `resId`、`txt`、`img` 作为歌单卡片。
- 推荐结果由咪咕按当天与账号状态下发，应用不做本地排序或个性化推断；未登录时返回的是匿名推荐。

### 账号歌单

登录后歌单页顶部的「我的音乐」只读展示账号自己的歌单，不新建、不收藏、不修改账号内容：

- `GET https://app.c.nf.migu.cn/pc/user/home-page/v2.0`：从 `userPrivateItems` 里找 actionUrl 含 `musicListId` 的「喜欢的音乐」入口，并读取 `myCreatedMusicLists.createdMusicLists` 与 `myCollectedMusicLists.collectMusicLists`。
- 点开任意歌单后复用公开歌单详情与歌曲接口（`resource/playlist/v2.0`、`MIGUM3.0/resource/playlist/song/v2.0`），按页加载、整单播放。
- 结果只留在内存里：登录成功（含带凭据启动）时自动读取一次，退出登录即清空，不写入本机偏好文件。

### 外部歌单导入

歌单页的「我的导入」只接受用户粘贴的公开分享链接，流程为：解析链接 → 读取外部歌单的曲目名与歌手 → 逐首搜索咪咕曲库 → 保存匹配结果。

| 平台 | 读取方式 | 实测限制 |
| --- | --- | --- |
| 网易云音乐 | `GET https://music.163.com/api/v6/playlist/detail?id=<id>&n=1000`（Referer `https://music.163.com/`） | 不带 `n=1000` 时匿名请求只返回前 10 首完整曲目；带上后返回整个歌单（实测 200 首）。 |
| QQ音乐 | `GET https://c.y.qq.com/qzone/fcg-bin/fcg_ucc_getcdinfo_byids_cp.fcg?disstid=<id>&…`（Referer `https://y.qq.com/`） | 缺少 Referer 返回 `invalid referer`；实测 393 首完整返回。 |
| 酷狗音乐 | `GET https://www.kugou.com/yy/special/single/<id>.html` | 网页版只公开前 30 首，页面出现「查看更多内容」时按部分导入并在界面标明；本机环境下 `mobilecdn` 接口证书无效，因此未使用。 |

- 短链接（`163cn.tv`、`c6.y.qq.com/base/fcgi-bin/u`、`k.kugou.com`）先跟随 302，再从最终地址或页面正文中提取歌单 ID。
- 匹配先做标题归一化（去括号注释、`feat.`、全半角与标点差异），标题完全一致优先；包含匹配必须同时有歌手重合，避免把翻唱或同名曲当成原曲。
- 单次最多扫描 500 首（并发 4），最多保存 20 个导入歌单，按来源链接去重；结果保存在本机 SharedPreferences。匹配途中遇到咪咕限流会立即停下并提示稍后再试，本次不保存。未匹配的曲目会列在导入歌单页底部，不会被静默丢弃。

### 登录方式

入口只有一个：桌面左下角的账号卡片，或移动端「我的」页的「账号与播放权限」。点开就是 `lib/widgets/account_center.dart` 这个弹窗——未登录时它内嵌原生登录表单（`lib/widgets/native_login_panel.dart`），已登录时同一屏改成简约版个人中心：头像、昵称、打码手机号、VIP 标识，以及登录凭据项数、登录时间、最近校验时间和播放权益说明，底部是「切换账号」与「退出登录」两个按钮。已经没有独立的登录入口页；系统浏览器登录与手动粘贴 Cookie 两个功能整体删除，对应的 `login_page.dart`、`account_login_card.dart`、`cookie_login_actions.dart` 与 `native_login_page.dart` 一并移除。

#### 退出登录与切换账号

两个按钮走同一段逻辑：先清掉安全存储里的登录凭据、登录票据与服务端会话快照（`MiguCookieStore.clearLoginCookies()` 与 `PassportTicketStore.clear()`），把本地登录状态归零并停掉前台保活（`AccountProvider.signOut()`），再停止播放、清空播放列表与歌词（`PlayerProvider.clearQueue()`），同时注销系统媒体控制。区别只在退出之后停在哪一屏：「切换账号」留在弹窗里，此时 `hasLogin` 为假，原生登录表单就地出现，直接登新账号；「退出登录」关掉弹窗并在首页提示「已退出登录，本机保存的凭据已清除」。两个动作都要先过一个确认弹窗，说清清除范围。

咪咕没有登出接口，这一步只发生在本机：服务端那份 `pacmtoken` 在它自己眼里仍然有效，应用不会、也无法通知它。登录票据同样被删掉，不会留到下一个账号。设置、搜索历史与导入的歌单都不在清除范围内；重新登录一次同样会整体覆盖旧凭据。

#### 登录失效时自动退出

除手动退出外，还有一种应用自己发起的退出，但它需要**两次独立取证**才生效。判定在 `MiguApiClient._noteFailure()` 里做，因为只有拦截器拿得到真实请求地址（`290001 请先登录` 是 HTTP 200 带回来的）：条件是本机确实带过 `pacmtoken`，且回绝来自 `isLoginScopedEndpoint()` 认下的账号接口（`/user/h5/user-info/`、`/pc/user/home-page/`、`/pc/user/h5/queryUserInfo/`）。满足时 `SessionRejectLedger.note()` 记一条证据并计一次数，再走 `AccountProvider.markSessionRevoked()`：本机有原生登录留下的票据时，先在后台用它换一次新 `pacmtoken`（`MiguPassportApi.renewSession()`，成功后由 `MiguCookieStore.applyRenewedCredentials()` 只覆盖同名凭据，不动官方播放器同步来的会话 Cookie）；换到了就清零计数、静默继续，失败波里的其余拒绝也不会再触发判定。票据不在本机、被咪咕拒绝或 10 分钟内已经试过一次，才进入原来的流程——计数不足 2 就只调 `markRejected()` 把状态降级为「登录可能已失效」，**凭据原样保留**；计数到 2 才确认作废：停掉前台保活，通过 `AccountProvider.onAutoSignOut`（在 `main.dart` 里接到 `signOut()` + `PlayerProvider.clearQueue()`）执行与手动退出完全相同的一套动作，并在登录面板顶部把原因写清楚：状态标签变成「登录已失效，已自动退出」，说明文字点名是咪咕拒绝了本机凭据、不是用户自己退的，还附上最近一次被拒的接口地址、HTTP 状态码与业务编码。左下角那张账号卡片此时也跟着换成同一句「登录已失效，已自动退出」和警示色图标，不藏着让用户以为是自己的正常未登录状态。这条说明只在重新登录时收起。

两次之间必须隔开 `SessionRejectLedger.confirmGap`（默认 30 分钟）：登录后的批量请求里，多个账号接口会因为同一个原因同时被拒，那是一波失败而不是两次独立取证。同理，账号接口只要有一次成功回包就把计数清零，避免旧账和新的一次凑成「确认失效」。

之所以最终要自动退而不是长期留着：咪咕没有 refresh token，留存票据也只能换一次；连票据都换不到新会话后，就没有任何恢复手段，留着只会让界面长期卡在「登录可能已失效」，而唯一的出路本来就是重新登录。**单次信号绝不足以定罪**——删本机凭据不可逆，而服务端轮换、单接口抽风、风控抖动都会回同样的东西。**HTTP 403 不参与失效判定**（`classifySessionProbe()` 只把 401 算 revoked）：那大概率只是这首歌没有权益，`markRejected()` 依旧只把状态标成「可能失效」并保留凭据，绝不动登录。歌词、封面、CDN 时效地址、公开搜索这些不要求登录的接口回 401，也只留证据、不计数。

#### 原生登录（短信验证码 / 账号密码）

1. 弹窗上半部分是当前登录状态（未登录 / 登录已失效，已自动退出 / 已保存登录凭据 / 登录凭据已验证 / 登录可能已失效 / 已登录，缺少音乐登录会话），下半部分是两个胶囊式页签切换的登录方式（`_ModeTabs`），整屏不出现网页。表单按紧凑样式排布：输入框不再另起字段标题，提示词即字段名，提交按钮是整宽描边的「登录」。
2. 短信方式填手机号后点「发送验证码」，按钮进入 60 秒倒计时（显示「30s 后重发」）；把收到的验证码填进来点「登录」。密码方式填账号与密码，密码框默认遮蔽、可点眼睛图标临时显示。手机号、验证码与密码没填齐时提交按钮保持禁用。
3. 咪咕若要求图形验证码，表单里会多出「图形验证码」一行：左边是输入框，右边是咪咕下发的那张图片，点图片就是官方的「换一张」。这一行出现后，不填字符提交按钮一直禁用；点提交时应用先让官方认一次你输入的字符，认过了才带着它重新提交登录，认不过就提示换一张重填。图片由你本人识别，应用不代答、也不引入任何识别能力。咪咕改要滑块这类本表单无法呈现的形式时，只在「需要官方页面协助」里说明并给出「打开咪咕官方登录页」入口。
4. 手机号、验证码与密码只在输入框内存里存在；提交成功后立刻清空验证码、密码与图形验证码输入框并关闭弹窗，再提示「登录成功：138\*\*\*\*0000」。表单下方常驻一个「改用咪咕官方页面登录」的小按钮，任何时候可以直接走官方页面。
5. 登录成功后写入安全存储的是 `token-validate` 下发的 `pacmtoken` 和本次登录票据。界面状态直接标记为「登录凭据已验证」（咪咕服务端刚刚发放了会话），并重启前台保活、拉一次账号资料。

原生登录走的是咪咕网页端自用协议，官方随时可能调整参数或加风控。图形验证码已经做成表单里的一行，由你自己看、自己输；除此之外一旦被拒，只剩官方页面登录这一条兜底路径，应用不会自动重试或后台重登（账号接口回绝时用留存票据换一次新会话，属于续期，不是重登）。

写入本机的登录凭据只有 `pacmtoken` 与那张登录票据——`uid` / `msisdn` 由官方签名上下文推导，登录响应里没有可靠对应值，猜错反而会让取链请求整体被拒。前台保活探测的门槛也只看 `pacmtoken`：原生登录拿到这一份凭据也会每 4–6 小时只读请求一次账号资料；账号资料接口本身不要求 `uid`，缺 `uid` 时最坏只回一条说不清的失败，归为 unknown，不会误报失效。若账号资料能正常显示头像昵称，说明这条凭据已经够用。

#### 咪咕官方页面登录（风控兜底，按需打开官方登录窗口）

1. 在账号弹窗里点「改用咪咕官方页面登录」（或风控提示下的「打开咪咕官方登录页」），此时才打开 `lib/pages/official_login_page.dart` 这个只承载官方通行证页面的登录窗口，在其中完成咪咕通行证登录。登录方式以官方页面为准；当前官方页面提供短信、密码或本机号码登录。
2. 登录地址由 `lib/services/auth/migu_passport_url.dart` 按官方页面的全页登录格式构造，除 `sourceid` 等官方参数外还带上 `relayState`（回跳地址为 `https://music.migu.cn/v5/`）；缺少它时通行证登录后不会回跳，页面会一直停在加载态。
3. 回跳后应用会短暂读取该窗口的 Cookie（约 16 秒，每 0.9 秒一次），只有出现对 `music.migu.cn` 生效的登录凭据（`pacmtoken`、`mg_auth_sid` 或 `migu-utoken-sessionid`）才算登录完成并导入。匿名访问咪咕网页本来就会写入的统计与设备 Cookie（`cookieId`、`mg_uem_user_id_*`、`migu-device-uuid`、`task-session-id`）一律不作为登录依据，只对通行证域生效的 Cookie 也不会触发导入、不清空网页会话。
4. 实测结论（真实账号，2026-10-20）：整页 WebView 里官方页面确实显示已登录（头像与会员标识都在），可读到的 13 项 Cookie 主要是 `LtToken`、`USessionID`、`mgnd_session_*` 等通行证级会话，其中包含 `pacmtoken`，但没有 `mg_auth_sid`。这不是读取能力的限制——`mg_auth_sid` 由页面脚本（js-cookie）写入，脚本写不出 HttpOnly，而 Windows 端读取走 CDP `Network.getCookies`，HttpOnly 也会返回。2026-10-21 定位到：音乐页自己的「登录」按钮并不整页跳转，而是在 `music.migu.cn` 页面内嵌一个 `passport.migu.cn/login?…&callbackURL=PostToken` 的 iframe，由父页面收下回票后用脚本写入 `mg_auth_sid`；把通行证页当整页顶层文档打开时缺少这个父页面，那一步换票回调不执行。不过 `pacmtoken` 仍会出现，原生 VIP 取链只需要它，因此登录窗口现在会以它为完成信号自动导入；等待窗口仍只有 16 秒。
5. 登录窗口顶部的地址栏显示当前真实域名与检测状态，用于区分“还停在通行证页”和“已回到音乐页但凭据未写入”。若未自动返回，可点击「我已登录，读取凭证」手动触发：读到音乐域登录凭据时按正常流程导入并清空网页会话；只读到官方 `mg_auth_*`（如 `mg_auth_pid`，说明换票尚未完成）时也导入，但保留网页会话并在提示中列出已看到的官方 Cookie 名称；只有统计类 Cookie 时只提示、不导入。提示中只出现 Cookie 名称，不显示任何 Cookie 值。
6. 读取成功后该窗口立即清理 Cookie 并关闭，应用自动回到首页，账号弹窗也一并关闭；其余界面上没有任何网页元素。

WebView 只出现在两个地方：按需打开的官方登录窗口临时加载通行证页面，播放页为 VIP 曲目内嵌咪咕官方网页播放器；账号弹窗、原生登录面板与其余界面都不加载任何网页。官方登录窗口通过系统 WebView 的 CookieManager 读取 Cookie（包含 HttpOnly 与会话 Cookie）；个别时机 CookieManager 读不到页面刚写入的条目，还会直接读页面自己的 `document.cookie` 作为兜底（只取名称与值）。读到的登录会话交给同一套安全存储与请求逻辑。内嵌播放器面板完全不接触 CookieManager。Windows 上两者使用相互隔离的用户数据目录；Android 共用系统 WebView 的 Cookie 库，退出登录页时只按咪咕站点逐条删除登录 Cookie。

Cookie 保存在系统安全存储中（Windows 是由 DPAPI 按当前账户加密的密文文件，落在应用数据目录；Android 使用 Keystore 派生密钥加密，且已关闭系统备份），仅发送给咪咕域名。旧版 SharedPreferences 中的明文数据会在首次启动时迁移，迁移并回读成功后才删除旧数据；迁移失败会保留旧数据并在界面提示，不会静默写回明文。

登录状态分为“已保存登录凭据”“登录凭据已验证”“登录可能已失效”，另有“已登录，缺少音乐登录会话”。带 `pacmtoken` 的 VIP 取链请求成功、原生登录刚换到音乐站会话或静默续期成功时标记为已验证，并把「账号接口被拒」的计数清零；只有要求登录的账号接口在本机确实带过 `pacmtoken` 时回 HTTP 401 或业务码 `290001 请先登录`，才算一次失效证据，单次证据只把状态标成「可能失效」并**保留凭据**，隔过 30 分钟后再次被拒才按上文「登录失效时自动退出」当场清掉本机凭据；403 只说明当前账号大概率没有这首曲目的权益，公开接口（歌词、封面、搜索）的 401 也只说那条资源拿不到，两者都不参与失效判定，不翻转也不清除登录。取链接口在业务层返回“没有可用地址”（如 `440022`）时只展示服务端文案，不改变登录状态；`listenSong.do` 的 `200002` 属于接口层拒绝，同样不改变状态。重启后不会直接沿用上次的“已验证”状态。原生登录只由用户当场发起，应用绝不自动重登；账号接口回绝时，原生登录留下的票据会静默换一次新会话（换不到才走上面的两次取证）；官方网页本身会续签会话，Windows 上内嵌播放器打开时由 `WebSessionSync` 把续签结果读回本机快照（Android 不读回，网页会话只留在系统 WebView 里）；其余情况只能被动保留服务端新的 Set-Cookie。

官方窗口导入提示的项数是写入时的数量；服务端随后用 `Max-Age=0` 删除的 Cookie 不会由本地快照复活，因此账号卡片上显示的项数可能更少（例如导入 8 项后剩 5 项）。每次重新登录都会清空旧快照与旧的服务端会话，避免不同账号混用。

若本机凭据里没有 `pacmtoken`、`mg_auth_sid` 或 `migu-utoken-sessionid` 这类登录凭据，界面会显示“已登录，缺少音乐登录会话”，VIP 播放会直接说明缺少 `pacmtoken`，而不是笼统地提示“登录可能已失效”，并且不会把状态标记为“已失效”。

VIP 曲目能否播放完全取决于咪咕是否按当前账号权益发放地址：应用只把本机凭据随请求发送，不做本地提权，也不下载或解密音频；被咪咕拒绝时，播放页的「官方播放器」面板仍可作为兜底——那是咪咕自己的页面，登录、鉴权、取链都在它那边完成。界面文案与错误提示按这一分工措辞，不承诺“登录后即可播放任意 VIP 曲目”。

## 平台能力

### Windows

- 应用内空格：播放 / 暂停（文本输入框聚焦时自动让位）。
- 全局快捷键：`Ctrl + Alt + 空格` 播放 / 暂停，`Ctrl + Alt + ←/→` 上一首 / 下一首。
- 可选的裸空格全局快捷键默认关闭，开启后会拦截所有应用的空格输入，包括本应用的文本输入。
- Windows 系统媒体卡片（SMTC）显示歌曲、歌手、封面与播放状态，键盘媒体键交由系统媒体会话处理。
- 原生标题栏跟随应用主题切换深浅色（DWM），窗口标题与初始大小由 `window_manager` 设置。
- 应用内空格与裸空格全局快捷键均可在「设置 → 快捷键」中单独开关。
- 桌面端的歌曲行（首页、搜索、歌单、导入歌单）需要双击才起播，单击只给出悬停反馈，避免浏览列表时误触换歌；双击起播后仍留在当前列表，播放页改由底部播放条点开。触屏端仍然单击即播并直接进入播放页。
- 「设置 → 桌面歌词」可开启独立于主窗口的原生歌词浮层：逐字颜色推进由浮层自己的定时器插值，Dart 侧只在换句、跳转与播放状态变化时重新对表，因此颜色跟随不再受进度上报频率限制。

### Android

- 播放时由 `flutter_media_session` 启动前台媒体服务，通知栏与锁屏可控制播放。
- `just_audio` + `audio_session` 管理音频焦点：来电或其他应用占用音频时自动暂停。
- 媒体按键的播放 / 暂停 / 上一首 / 下一首同步到应用播放队列。
- 通知权限由媒体会话插件在激活时请求；应用退出后不保留后台常驻服务。

- **续期与换号 / 退出并发**：覆盖旧续期在网络返回、Cookie 写入、落盘三个窗口分别遇到官方页面登录、原生登录或退出时，都不会把旧账号的 `pacmtoken` 写回新会话、不会覆盖新票据，也不会在退出后把会话恢复成已验证或重新启动保活，且同一会话内的正常续期仍然生效。
- **登录弹窗交互**：验证码行的展开时机、未填字符时提交保持禁用、点图片触发 `showType=1` 的「换一张」，以及先认一次答案再重新提交登录的顺序。
- **隐私政策与关于页**：锁定条目数量与结构、必须披露的实现事实（加密提交、安全存储落点、验证码只由本人识别、`deviceId` 与假指纹来源、两处网络例外、播放器目录不被清除）、禁止出现的夸大承诺，并校验常量里出现的每个咪咕域名都在政策正文里点名、登录弹窗底部的「隐私政策」按钮点开就是完整正文并能在关闭后回到登录面板，关于页则不得再出现正文或标题（用户 2026-10-23 要求删掉那块）。
- **个人中心**：锁定「同一个弹窗两种形态」：登录后卡片点开是个人中心而不是登录表单，退出登录与切换账号都要先过确认弹窗，确认后安全存储里的凭据与账号快照被删干净、保活被停掉、播放器队列被清一次，退出关掉弹窗而切换留在弹窗里就地回到登录表单；`MiguCookieStore.clearLoginCookies()`、`AuthSessionStore.clear()`、`AccountProvider.signOut()` 与 `PlayerProvider.clearQueue()` 各有独立用例，包括删除失败时本次运行仍然退出并给出提示，以及清空队列不动播放顺序、音量与倍速这些偏好。
- **登录失效自动退出**：403 的 `markRejected()` 既不停保活也不触发退出，只有 `markSessionRevoked()` 会走 `onAutoSignOut`；确认后安全存储里的凭据与状态记录一起消失、状态标签变成「登录已失效，已自动退出」并带上点名咪咕的说明文字，弹窗就地退回登录表单、播放器被清一次，而重新登录会把这条说明收起；左下角卡片在未登录但有这条说明时，副标题从通用的「点击登录，使用自己的账号权益」换成同一句失效说明。
- **Android 组件**：设计 token 的间距 / 圆角 / 48dp 触控下限、底部导航胶囊与唱片入口回调、选中态不垫色块而靠描边到实心的图标形变与主题色文字、切到新选中那格时背后闪一块淡色切面（圆角跟胶囊同一档，两端都是半圆，不会露出杵在唱片旁边的直边；第一帧就到峰值、定住 100ms、再 400ms 线性淡回全透明，被离开的那格不跟着闪，尺寸全程不变；关掉系统动效时整块不出现；这一格的圆形水波纹一并关掉（圆形波纹会和胶囊形对不上，峰值那一瞬像两个形状叠在一起），改用一层同形状的按下底色补回按住时的反馈——它比切面峰值淡一档，且和切面共用同一层、取两者更浓的那个，所以松手那瞬两层不会叠得比峰值还重；中间那颗唱片仍是普通水波纹，它本来就是圆的）、迷你条与循环进度环共用同一套几何、玻璃面板默认投影分远近两层且每层偏移都不小于 σ（否则最浓的一档压在面板自己下沿上，看着就是胶囊底下糊了一道灰）、定高壳层在两倍字体下不溢出、操作表与单选面板的开合与层级、播放控制宫格只摆倍速 / 音质 / 定时三格并在子面板里真正改到播放器与设置、骨架屏与跑马灯的截断语义，以及歌曲模型同时保留 200px 缩略档与 800px 大图档（列表用小的、整屏播放页用大的）。
- **账号切换与会话并发**：资料 / 歌单刷新在发起时记录会话代数和请求序号，旧账号的回包（含失败结果）不会覆盖新账号、不会清掉新请求的加载态，也不会让新账号的刷新被旧加载挡住；续期占用改为按会话代数判断，旧账号挂起的续期既不占用新账号的名额，结束时也不会清掉新会话的续期标记；官方导入与原生登录在票据清理、Cookie 写入、状态落盘等每个异步边界后复核会话代数，期间退出或换号时旧流程不再触发会话建立回调、不再重启保活或恢复票据；播放请求在发起时记录代数，旧请求晚到的 401 与成功回包不会改动新会话的认证状态、Cookie、回绝账本或自动退出，而同一会话内的 401 仍照常判定失效。

## 已知限制

- 咪咕公开接口并非稳定 API，可能出现字段变化、限流或地域限制；播放链接带时效。
- 原生登录走的是咪咕网页端自用协议，官方随时可能改参数或加风控。图形验证码已经做进登录表单：图片按官方下发原样显示，由你本人识别后输入，应用不代答；官方改要滑块这类无法呈现的形式，或接口再调整时，只能改用官方页面登录，应用不会自动重试。官方页面的「本机号码一键登录」依赖基站与 IP 判定，桌面端不可用，因此原生登录只提供短信验证码与账号密码两种。
- VIP 曲目只能按咪咕账号权益播放：账号无对应权益时服务端不会下发地址，应用不做本地提权。
- 外部歌单依赖各平台公开接口或公开页面，可能随时调整：酷狗网页版只公开前 30 首，网易云与 QQ音乐也可能改变返回字段；导入按标题与歌手匹配，重名、翻唱或信息不全时可能漏配或配错，未匹配项会在页面上列出。
- 单次导入最多扫描 500 首、最多保存 20 个歌单，属于对第三方平台限流与应用响应速度的折中；匹配并发 4，遇到咪咕限流会整单停下并提示稍后再试。
- 应用没有做单实例限制：请勿同时运行多个窗口或进程，多进程同时写本机凭据与偏好没有经过验证。
- Android 发布包当前使用 debug 签名，仅适合个人本地安装；如需长期使用请自行配置 release 签名。
- Windows 全局快捷键若被其他程序占用会注册失败，应用内空格与 SMTC 媒体键仍可使用。
- 开发环境已安装 Visual Studio 2022 Build Tools 与 Windows SDK，Windows Release 构建与启动验证通过（2026-10-22 连续 10 次启动全部存活）；Android SDK 已安装，release APK 已完成构建并安装到真机启动（2026-10-22）。
- Windows 端曾出现启动阶段随机闪退（`0xc0000005`，符号化后位于 Flutter 引擎 `AccessibilityBridge::CreateRemoveReparentedNodesUpdate`，日志伴随 `Failed to update ui::AXTree`），属于引擎无障碍桥缺陷（flutter/flutter#175041，截至当前版本仍未修复）。现在由 `windows/runner/flutter_window.cpp` 在主窗口和 Flutter 视图子窗口上拦下 `WM_GETOBJECT`，引擎不再建立无障碍树，因此不再崩溃；代价是屏幕阅读器等辅助技术无法读取本应用窗口。等引擎修复后删掉这段拦截即可恢复无障碍。
